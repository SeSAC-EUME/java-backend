# 006. UserChat AI 다중 채팅 수정 계획서

## 개요

현재 UserChat은 "사용자 간 채팅"으로 구현되어 있으나, 실제 요구사항은 **"AI 다중 채팅"**입니다.
- **EumeChat**: 유저당 1개의 AI 채팅방 (고정)
- **UserChat**: 유저가 여러 개의 AI 채팅방을 생성 가능

이 계획서는 UserChat을 EumeChat과 동일한 AI 채팅 방식으로 수정하는 작업을 정의합니다.

---

## 중요: n8n Webhook URL 구분

**EumeChat과 UserChat은 서로 다른 n8n webhook URL을 사용합니다.**

| 채팅 타입 | 환경변수 | 설정 키 | 용도 |
|----------|---------|---------|------|
| EumeChat | `N8N_EUME_CHAT_WEBHOOK_URL` | `n8n.webhook.eume-chat.url` | 이음이 AI (1:1 고정 채팅) |
| UserChat | `N8N_USER_CHAT_WEBHOOK_URL` | `n8n.webhook.user-chat.url` | 다중 AI 채팅 |

이를 통해 각 채팅 타입별로 다른 AI 에이전트 또는 워크플로우를 연결할 수 있습니다.

---

## 현재 구현 vs 목표 구현

### 현재 구현 (사용자 간 채팅)

| 항목 | 현재 상태 |
|------|----------|
| Request DTO | `messageContent` + `messageType` (사용자가 타입 지정) |
| Response DTO | 단일 메시지 (`senderId`, `senderName` 포함) |
| Service | 메시지 저장만 수행 (AI 응답 없음) |
| Entity | `eumeUser` 필드가 "발신자" 개념으로 사용됨 |

### 목표 구현 (AI 다중 채팅)

| 항목 | 목표 상태 |
|------|----------|
| Request DTO | `messageContent`만 받음 (EumeChat과 동일) |
| Response DTO | `userMessage` + `aiMessage` (EumeChat과 동일 구조) |
| Service | n8n webhook 호출하여 AI 응답 받기 |
| Entity | `messageType`: "USER" 또는 "AI"로 구분 |

## 수정 대상 파일

### Phase 1: DTO 수정

#### 1.1 Request DTO
- **파일**: `UserChatContentCreateRequest.java`
- **변경**: `messageType` 필드 제거, `messageContent`만 유지

```java
// Before
public record UserChatContentCreateRequest(
    @NotBlank String messageContent,
    @NotBlank String messageType
) {}

// After
public record UserChatContentCreateRequest(
    @NotBlank(message = "메시지 내용은 필수입니다")
    String messageContent
) {}
```

#### 1.2 Response DTO
- **파일**: `UserChatContentCreateResponse.java`
- **변경**: 단일 메시지 → `userMessage` + `aiMessage` 구조로 변경

```java
// Before
public record UserChatContentCreateResponse(
    Long id,
    Long senderId,
    String senderName,
    String messageType,
    String messageContent,
    LocalDateTime createdAt
) {}

// After
public record UserChatContentCreateResponse(
    UserChatContentResponse userMessage,
    UserChatContentResponse aiMessage
) {
    public static UserChatContentCreateResponse from(
            UserChatContent userContent,
            UserChatContent aiContent
    ) {
        return new UserChatContentCreateResponse(
                UserChatContentResponse.from(userContent),
                UserChatContentResponse.from(aiContent)
        );
    }
}
```

## 고려 사항

### 1. EumeChat vs UserChat 비교

| 구분 | EumeChat | UserChat |
|------|----------|----------|
| **채팅방 개수** | 유저당 1개 (고정) | 유저당 무제한 |
| **n8n Webhook URL** | `N8N_EUME_CHAT_WEBHOOK_URL` | `N8N_USER_CHAT_WEBHOOK_URL` |
| **설정 키** | `n8n.webhook.eume-chat.url` | `n8n.webhook.user-chat.url` |
| **AI 에이전트** | 이음이 전용 에이전트 | 별도 에이전트 (다른 성격/목적 가능) |
| **용도** | 기본 상담/대화 | 사용자 정의 주제별 대화 |

### 2. n8n Webhook 분리 이유
- **다른 AI 에이전트 연결 가능**: UserChat은 EumeChat과 다른 성격의 AI를 연결할 수 있음
- **워크플로우 분리**: 각 채팅 타입별로 다른 n8n 워크플로우 구성 가능
- **독립적 관리**: 한쪽 webhook에 문제가 생겨도 다른 채팅에 영향 없음

### 3. 기존 데이터 호환성
- 기존 UserChat 데이터가 있다면, `messageType` 값이 "USER"/"AI"가 아닌 경우 마이그레이션 필요
- 신규 프로젝트라면 데이터 마이그레이션 불필요

### 4. 테스트
- Service 단위 테스트 추가 (n8n webhook mock)
- Controller 통합 테스트 추가
