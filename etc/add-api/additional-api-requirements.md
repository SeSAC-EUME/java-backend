# 추가 API 요구사항 개요

> 이 문서는 etc/add-api 폴더의 시안 이미지를 기반으로, **어떤 기능(도메인)** 이 추가로 필요해 보이는지 간단히 정리한 문서입니다.
> 상세한 스펙/에러코드/DTO 설계는 이후 구현 계획서에서 다룹니다.

---

## 1. User 영역에서 필요한 기능

### 1.1 사용자 홈(인덱스) 관련
- 최근 대화 요약/추천 카드 조회 API
- 오늘의 감정 상태/간단 지표 조회 API
- 공지사항 또는 서비스 안내 배너 조회 API

### 1.2 사용자 채팅 화면
- 기존 EumeChat / UserChat 목록 조회 API 재사용 + "즐겨찾는/최근" 정렬 옵션
- 특정 채팅방의 **간단 요약 정보** 조회 (마지막 대화 일시, 상대/이음이 정보 등)
- 채팅방별 기본 설정(알림 여부, 고정/핀 여부 등) 조회 및 변경 API

### 1.3 사용자 설정 화면
- 프로필 정보 조회/수정 API (닉네임, 프로필 이미지 등)
- 알림 설정 조회/수정 API (푸시/이메일/문자 수신 여부 등)
- 개인정보/약관 동의 현황 조회 API
- 계정 탈퇴/비활성화 요청 API

---

## 2. Admin 영역에서 필요한 기능

### 2.1 관리자 로그인
- 기존 Admin 로그인 API 재사용
- "소속 기관" 드롭다운용 기관 목록 조회 API (기본적으로 `Sigungu` 엔티티를 활용하되, 필요 시 별도 기관 테이블로 확장 가능)
- "로그인 상태 유지" 체크박스용 토큰 만료/리프레시 정책 연동

### 2.2 대시보드
- 전체/활성 이용자 수, 신규 이용자 수, 평균 만족도 등 **요약 지표 조회 API**
- 정서 위험 감지 알림 목록 조회 API (이용자 정보, 위험도, 필요 조치 등)
- 최근 7일/30일 등의 기간별 감정 분포 차트용 통계 조회 API
- 주간 대화 활동(총 대화 수/메시지 수 등) 통계 조회 API

### 2.3 이용자 관리
- 검색/필터 기능이 포함된 이용자 목록 조회 API
  - 이름, 주소, 전화번호, 상태(활성/비활성), 위험도, 연령 등 조건
- 개별 이용자 상세 정보 조회 API (기존 Admin User Detail와 연계)
- 이용자 상태 변경 API (활성/비활성 전환 등)
- 일괄 작업용 선택된 이용자에 대한 배치 처리 API (예: 알림 발송 예약)
- Excel 내보내기를 위한 이용자 데이터 다운로드 API

### 2.4 감정 모니터링 / 대화 분석
- 기간/이용자/감정 상태별 필터가 가능한 **대화 통계 조회 API**
  - 총 대화 수, 평균 대화 시간, 총 메시지 수 등
- 주요 대화 주제(카테고리)별 집계 데이터 조회 API
- 키워드 클라우드용 자주 등장하는 키워드 목록 조회 API
- 대화 분석 결과를 기반으로 한 만족도/감정 점수 추세 조회 API

### 2.5 긴급 상황
- 긴급 요청 목록 조회 API (대기/처리 완료/취소 등 상태별)
- 개별 긴급 요청 상세 조회 및 처리 결과 기록 API
- 긴급 상황 통계(요청 건수, 평균 응답 시간 등) 조회 API

### 2.6 보고서
- 선택한 기간/필터에 따른 **보고서 데이터 집계 API**
  - 이용자 활동, AI 대화, 감정 분석, 긴급 상황 등 여러 위젯용 통계
- PDF/Excel 보고서 생성 요청 API (비동기 생성 시 상태 조회 포함 가능)
- 일별 통계 상세(일자별 활성 이용자 수, 대화 수, 긴급 요청 수 등) 조회 API

### 2.7 시스템 설정
- 기관/관리자 프로필 및 권한 설정 조회/수정 API
- 감정 위험 임계값, 알림 발송 규칙 등 시스템 파라미터 조회/수정 API
- 로그/감사 기록 조회 API (누가 어떤 설정을 변경했는지)

---

## 3. 다음 단계 제안

1. 위에서 정리한 기능들을 기준으로, 기존 `etc/docs` 구현 계획서에 **새 섹션(예: v4 추가 기능)** 으로 편입합니다.
2. 실제로 필요한 것만 선별하여, 우선순위/개발 페이즈(Phase 1~3)를 다시 정의합니다.
3. 각 기능별로 상세 API 스펙(엔드포인트, DTO, 에러코드)을 별도 문서로 확장합니다.
